[CONTEXTO COMPLETO — PROYECTO RIPTIDE]

Soy desarrollador Android (Kotlin + Jetpack Compose), desarrollador web y tengo experiencia con Kotlin Multiplatform (KMP). Estoy desarrollando una app personal llamada Riptide en mi tiempo libre, partiendo de cero como proyecto propio.

---

CONCEPTO DE LA APP

App de productividad con ecosistema marino que crece con la constancia. La puntuación existe internamente pero nunca se muestra como número. El feedback es siempre emocional: mensajes, crecimiento visual del estanque, sensación de progreso sin métricas explícitas. La constancia construye algo bonito. El abandono lo pausa. Nunca lo destruye.

Inspirado en Forest, pero más profundo y personal — orientado a la sensación, no a los números.

---

STACK TÉCNICO

- Kotlin Multiplatform con Compose Multiplatform (una sola UI para Android e iOS)
- Proyecto generado con el KMP Wizard de JetBrains (kmp.jetbrains.com)
- La estructura no tiene carpeta shared: todo vive en composeApp/src/
- commonMain: lógica de negocio, modelos, repositorios, ViewModels, UI
- androidMain / iosMain: implementaciones específicas de plataforma
- Persistencia: Room (local, offline-first), versión 6
- IDs String (UUID) desde el primer día para facilitar sincronización futura
- Capa repositorio que abstrae el origen de datos (fácil migración a Ktor en v4)
- Patrón MVVM

LÓGICA DE CATEGORÍAS MARINAS (MarineCategoryAssigner)

Redistribución automática al crear/editar/eliminar bloques. Nunca visible al usuario.
1 bloque → 5 cat | 2 → 3+3 | 3 → 2+2+2 | 4 → 2+1+1+1 | 5+ → 1 cada uno
La experiencia acumulada en EcosystemState se mantiene intacta.
Se llama en: DataSeeder, MainViewModel (insert/update/deleteBlockAndReassign).

---

LÓGICA RECURRENTES (RecurringTaskGenerator)

generateUpTo(from: LocalDate, daysAhead: Int = 7): genera instancias DayTask para cada
  RecurringTaskDef activo en los próximos N días si no existen ya.
  Instancias generadas como TaskSchedule.OneTime con sourceTaskId = def.id
Se llama en MainViewModel.init y al crear/actualizar tarea recurrente.

Edición de tareas recurrentes (MainScreen + MainViewModel):
  — Al editar tarea con sourceTaskId != null: diálogo previo "¿Qué quieres editar?"
      · "Solo esta ocurrencia" → updateOneTimeTask (solo esa instancia)
      · "Esta y todas las futuras" → updateRecurringTask (actualiza def + regenera)
  — updateRecurringTask(sourceId, title, blockId, time, recurrence):
      actualiza RecurringTaskDef, borra instancias PENDING futuras, llama generateUpTo

LÓGICA DE EXPERIENCIA Y NIVELES

EcosystemLevelCalculator (commonMain, object):
  xpForLevel(n):
    nivel 1 = 0 XP
    nivel 2 = 1 XP    ← garantiza primer desbloqueo con 1 sola tarea completada
    nivel 3 = 21 XP   (+20)
    nivel 4 = 61 XP   (+40)
    nivel 5 = 126 XP  (+65)
    nivel 6 = 226 XP  (+100)
    nivel 7 = 376 XP  (+150) ... cada costo ×1.5 del anterior
  levelForXp(xp): nivel actual para un total de XP dado
  xpInCurrentLevel(xp): XP acumulada dentro del nivel actual
  xpForNextLevel(level): XP necesaria para completar el nivel actual
  nightBonus(score, bestStreak):
    — score>=1.0 → +50 XP | score>=0.7 → +25 XP | score>=0.4 → +10 XP
    — bestStreak * 5 XP adicionales
  XP_PER_TASK = 10

EcosystemProcessor (commonMain):
  addXpForTask(categories): List<CreatureSpec>
  addNightBonus(score, bestStreak, categories): List<CreatureSpec>
  — si el EcosystemState no existe para esa categoría, lo crea
  — actualiza currentLevel con EcosystemLevelCalculator
  — detecta criaturas desbloqueadas comparando oldLevel vs newLevel

Flujo XP:
  Al completar tarea → toggleTaskCompleted → addXpForTask → si hay nuevas → pendingUnlocks en UiState
  Al resumen nocturno → NightSummaryProcessor.processDay → addNightBonus → si hay nuevas → DataStore

FLUJO DE DESBLOQUEO DE CRIATURAS

1. EcosystemProcessor devuelve List<CreatureSpec> recién desbloqueadas
2. Tiempo real: MainViewModel añade a pendingUnlocks en UiState directamente
3. Resumen nocturno: NightSummaryProcessor persiste emojis en DataStore
4. Al arrancar: checkPendingUnlocks() lee DataStore → añade a UiState → limpia DataStore
5. Orden de diálogos al arrancar: pendingSummary primero → pendingUnlocks en cola
6. Diálogo de desbloqueo: emoji + mensaje + campo nombre obligatorio
7. confirmUnlock(spec, nickname): guarda MarineCreature en BD + drop(1) de la cola
8. dismissUnlock(): descarta sin nombre + drop(1)

RESUMEN NOCTURNO

NightSummaryProcessor.processDay (idempotente):
  1. Si ya existe DaySummary → return
  2. Expira PENDING → EXPIRED
  3. score = completadas / total
  4. blockStreakProcessor.processDay → Map<String, Int>
  5. ecosystemProcessor.addNightBonus → List<CreatureSpec>
  6. Persiste nuevos unlocks en DataStore
  7. buildMessage → guarda DaySummary

Mensajes base:
  0.0 → "Las corrientes cambian. Mañana el mar sigue ahí."
  <0.4 → "Algo se movió hoy. Eso cuenta."
  <0.7 → "Buen empuje hoy."
  <1.0 → "El estanque está vivo."
  1.0  → "Hoy el estanque brilló."

Flujo al arrancar (MainActivity.onCreate):
  1. seedIfEmpty(db, assigner)
  2. Procesa ayer con NightSummaryProcessor (fallback)
  3. Planifica WorkManager con hora guardada
  4. viewModel.reload() → checkPendingSummary + checkPendingUnlocks → diálogos
