[CONTEXTO COMPLETO — PROYECTO RIPTIDE]

Soy desarrollador Android (Kotlin + Jetpack Compose), desarrollador web y tengo experiencia con Kotlin Multiplatform (KMP). Estoy desarrollando una app personal llamada Riptide en mi tiempo libre, partiendo de cero como proyecto propio.

---

CONCEPTO DE LA APP

App de productividad con ecosistema marino que crece con la constancia. La puntuación existe internamente pero nunca se muestra como número. El feedback es siempre emocional: mensajes, crecimiento visual del estanque, sensación de progreso sin métricas explícitas. La constancia construye algo bonito. El abandono lo pausa. Nunca lo destruye.

Inspirado en Forest, pero más profundo y personal — orientado a la sensación, no a los números.

---

STACK TÉCNICO

- Kotlin Multiplatform con Compose Multiplatform (una sola UI para Android e iOS)
- Proyecto generado con el KMP Wizard de JetBrains (kmp.jetbrains.com)
- La estructura no tiene carpeta shared: todo vive en composeApp/src/
- commonMain: lógica de negocio, modelos, repositorios, ViewModels, UI
- androidMain / iosMain: implementaciones específicas de plataforma
- Persistencia: Room (local, offline-first), versión 8
- IDs String (UUID) desde el primer día para facilitar sincronización futura
- Capa repositorio que abstrae el origen de datos (fácil migración a Ktor en v5)
- Patrón MVVM

LÓGICA DE CATEGORÍAS MARINAS (MarineCategoryAssigner)

Redistribuye solo entre categorías desbloqueadas (isUnlocked=true), excluyendo DECORATION.
Requiere EcosystemStateRepository.getUnlocked().
Llamada en: DataSeeder (después de crear EcosystemStates), MainViewModel, BlockFormViewModelFactory.

IMPORTANTE: el DataSeeder debe crear los EcosystemStates ANTES de llamar a assigner.reassign(),
o de lo contrario getUnlocked() devuelve vacío y los bloques no reciben categorías.

LÓGICA DE EXPERIENCIA Y NIVELES

EcosystemLevelCalculator:
  nivel 2=1 XP, nivel 3=21, nivel 4=61, nivel 5=126, nivel 6=226... (×1.5 por nivel)
  XP_PER_TASK = 10

EcosystemProcessor(ecosystemStateRepository, marineCreatureRepository):
  addXpForTask(categories):
    — si categories vacío → reparte entre todas las categorías desbloqueadas (no DECORATION)
    — xpEach = 10 / targets.size (floor, sobrante se pierde)
  addNightBonus(score, bestStreak, categories): igual con bonus nocturno
  addXp(category, xp):
    — oldLevel = 1 si estado no existía, si no existing.currentLevel
    — actualiza EcosystemState (crea con isUnlocked=category.isUnlockedByDefault si no existe)
    — detecta criaturas desbloqueadas por nivel cruzado (oldLevel+1)..newLevel
    — reparte xp/N entre criaturas desbloqueadas de la categoría (floor)
    — actualiza experience y creatureLevel de cada criatura
  unlockCategory(category): marca isUnlocked=true

Nivel de criatura individual:
  — misma curva que EcosystemLevelCalculator
  — recibe xp/N por evento (N = criaturas desbloqueadas de esa categoría)
  — criatura recién desbloqueada NO recibe XP hasta el siguiente evento
  — creatureLevel afecta tamaño (0.8x nivel 1, +10% por nivel) y velocidad de nado

FLUJO DE DESBLOQUEO DE CRIATURAS

Al completar tarea → addXpForTask → List<CreatureSpec> nuevas → pendingUnlocks en UiState
Al resumen nocturno → addNightBonus → List<CreatureSpec> → DataStore
Al arrancar → checkPendingUnlocks → DataStore → UiState
Orden diálogos: pendingSummary → pendingUnlocks
Diálogo: emoji + nombre obligatorio
confirmUnlock(spec, nickname) → MarineCreature(experience=0, creatureLevel=1) → drop(1)

ECOSISTEMA VISUAL

AquariumCreatures recibe:
  ecosystemByCategory: Map<MarineCategory, EcosystemState>
  creatureLevelBySpecies: Map<CreatureSpecies, Int>
  creaturesData: List<MarineCreature>
  freezeState: CreatureFreezeState
  onCreatureLongPress: (MarineCreature, CreatureSpec) -> Unit

Filtro: state.isUnlocked && state.currentLevel >= spec.unlockLevel

Tamaño: baseSize * (0.8f + (creatureLevel - 1) * 0.10f)
Velocidad: swimDuration / max(0.3f, 1f + (creatureLevel-1) * speedScalePerLevel)

Zona de nado: asignada por especie (SwimZone). personalYFraction distribuye la base Y
dentro de la banda, evitando que criaturas de la misma zona estén a la misma altura.

Sistema de movimiento por capas (criaturas nadadoras):
  1. Onda primaria — waveCount (entero) → sin salto en loop
  2. Onda secundaria — waveCount·PHI (irracional) → patrón aperiódico
  3. Deriva lenta — driftSpeed fraccionario → eje Y siempre diferente entre ciclos
  4. Acoplamiento vertical — verticalCoupling: arco ligado a posición X (delfín salta)
  5. Microwobble — alta frecuencia (~1.5Hz), simula aleta/cola
  6. Perturbación X — xErraticness: microaceleraciones horizontales (clownfish, medusa)

Criaturas fijas: ondeo de corriente escalado por fixedWobbleScale (0=rígido, 1.8=anemona).
Hit-testing: `findHitCreature` compara offset del toque contra posiciones reales del último
frame dibujado (creaturePositions). Un único pointerInput en el Layout — no Boxes superpuestos.
Freeze on tap: la criatura se congela en su posición al pulsar; se descongela en onDismiss.

RESUMEN NOCTURNO

NightSummaryProcessor.processDay (idempotente):
  Evalúa: OneTime con date<=fecha resumen O completadas sin fecha.
  Excluye: POSTPONED, tareas futuras no completadas.
  Expira PENDING evaluables → score → streaks → bonus XP → unlocks → DaySummary.
